## Why

当前公开 API 已支持单份 Markdown 需求的 AI 评审和人工审批，但无法列出项目评审、恢复每个 finding 的人工决策状态，也未强制逐点处理完成后才能最终确认。需要补齐前端工作台依赖的共享契约。

## What Changes

- 扩展公开查询契约，提供项目内评审任务列表、文档显示信息和每条 finding 的最新人工决策，使页面刷新后可以恢复审核进度。
- 强化 finding 决策幂等语义，并要求所有评审点完成有效人工决策后才能最终批准文档。
- 本变更会修改前后端共享的公开 HTTP API 和评审工作流契约，但保持现有创建评审、单条决策和最终审批请求兼容。

## Capabilities

### Modified Capabilities

- `public-contracts`: 增加评审任务列表、文档元数据、finding 决策状态及逐点审核完成后才能最终确认的共享契约。

## Impact

- 扩展 `backend/` 的评审查询响应、列表能力和人工决策读取模型，并补充 API、服务及持久化测试。
- 更新根 OpenSpec 公共契约；对应前端组件 change 从 `frontend/openspec/` 引用该契约。
- 无破坏性 API 变更；现有客户端可忽略新增响应字段和列表端点。

## Non-goals

- 不定义前端目录选择、页面布局或客户端状态管理；这些属于前端组件 change。
- 不在本次变更中实现用户管理、登录页或新的身份提供方。
- 不实现多人抢占、任务分派、审核 SLA、通知或实时协作。
- 不改变 AI 的八个评审维度、模型选择策略或知识库索引流程。
