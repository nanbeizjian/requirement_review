# Repository Agent Instructions

## Scope

These instructions apply to the entire repository. A nested `AGENTS.md` may add component-specific requirements but cannot weaken these rules.

## OpenSpec workflow

- Treat `openspec/specs/` as the source of truth for public contracts shared by frontend, backend, and integrations.
- Put proposed cross-component changes under `openspec/changes/` and validate them before implementation.
- Public contracts include HTTP APIs, authentication and authorization, project isolation, shared domain schemas, error responses, compatibility, and cross-component workflows.
- Do not duplicate public contracts inside component OpenSpec stores. Reference the root specification instead.
- When a component change affects a public contract, update the root OpenSpec change first.
- Run `openspec validate` from the repository root for root changes and from each affected component for component changes.

## Engineering rules

- Preserve frontend/backend separation. Backend code and backend-only tooling belong under `backend/`.
- Never commit credentials, `.env` files, virtual environments, caches, generated bytecode, or local IDE state.
- Keep changes scoped, add tests for behavior changes, and use conventional commit messages.
- Human approval is required before finalizing requirement-review decisions or changing public contracts.
